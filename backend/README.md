# 行业数据分析引擎后端

**赛题五：面向行业数据的智能实体挖掘与关系建模（中国软件与技术服务股份有限公司 命题）**

本仓库实现赛题要求后端（Python + FastAPI）：
- **任务一 · 实体识别与自动化提取**：解析招采标讯公告 HTML 与附件（zip 内含 doc/docx/xlsx/pdf 等），自动化抽取 7 个关键字段（产品服务名称 / 品目 / 品牌（产品供应商）/ 规格型号 / 单价 / 数量 / 总价），并附带抽取采购单位、中标供应商、参与投标方、项目名称、项目金额等建模字段。
- **任务二 · 用户画像建模与关系分析**：构建「采购单位 — 中标供应商 — 投标参与方」关系模型，实现 5 大业务场景查询（合作分析、高频投标方与协同组合、共同竞标主体、共同合作采购单位、共同竞标项目）。
- **任务三 · 分析检索平台（后端部分）**：数据集批量上传自动解析入库、标的物全字段检索筛选、公告/主体管理、统计概览与知识图谱数据导出；并内置可视化平台页面（`/platform`，数据看板/检索/场景/图谱/导入，ECharts 本地化可离线演示），亦可由 Vue 前端调用同一套 API。

## 环境要求

- Python >= 3.10（开发验证环境：Python 3.14）
- 本机端口可绑定（默认 8000）

## 安装

```bash
cd backend
pip install -r requirements.txt
```

## 快速开始

```bash
# 1) 导入官方样例数据集(html 公告 + zip 附件, 同名配对)
python -m app.cli ingest ../sample_dataset --engine rule

# 2) 启动 API 服务 (文档: http://127.0.0.1:8000/docs)
python run.py --port 8000
# 或者
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 数据集格式

与赛事官方规范一致：**一篇公告对应一个 html 文件和一个（如有）同名 zip 附件包**。

```
dataset/
├── t20260202_26139731.html      # 公告详情页(中国政府采购网样式)
└── t20260202_26139731.zip       # 附件包(含 doc/docx/xlsx/pdf/图片)
```

支持三种形态，均可由 `discover_dataset()` 自动发现：
1. 目录下平铺 html + 同名 zip；
2. 每条公告独立子目录；
3. 整个数据集打包为 zip（自动解压后处理，含 API 上传）。

## 抽取引擎（任务一）

`app/extraction/` 分层设计：

| 模块 | 说明 |
| --- | --- |
| `html_parser.py` | 公告 HTML 结构化解析：公告概要表、中标(成交)信息、主要标的信息表格（表头列映射 + `；`多值拆分 + 金额/数量归一化）。 |
| `attachments.py` | 附件解析：zip 解压 → docx/openpyxl/pypdf/python-pptx 按格式抽取文本与表格；`.doc` 走 LibreOffice 转换；图片可挂接 OCR。 |
| `llm_engine.py` | OpenAI 兼容大模型抽取（Qwen/DeepSeek），JSON 结构化输出（`response_format=json_object`）。 |
| `pipeline.py` | 编排：HTML 规则解析 → 附件表行补充 →（可选）LLM 增强/覆盖 → 状态评估。 |

引擎二选一（环境变量 `EXTRACTION_ENGINE`，默认 `rule` 离线可用）：

```bash
# 大模型引擎(推荐用于提高泛化/召回; 需配置 API)
export LLM_API_KEY=sk-xxx
export LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1   # 或 DeepSeek 等
export LLM_MODEL=qwen-plus
export EXTRACTION_ENGINE=hybrid    # rule|llm|hybrid
```

大模型只作为"规则引擎之上的增强层"：规则引擎保证离线、高速（单篇毫秒级）；`llm`/`hybrid` 模式用于提升复杂公告的召回与准确性，符合赛题"优先采用 Qwen/DeepSeek 开源国产大模型 + 提示工程"的要求。

## 数据模型（任务二）

```
organizations      市场主体(按规范化名称合并): 采购单位/中标供应商/投标参与方/产品供应商/代理机构
announcements      公告主表(标题哈希去重, 总金额=万元, 覆盖式重复导入)
target_items       标的物(7 字段, 单价/总价单位=元, source=html|attachment)
participations     公告×主体参与关系(角色+包号+金额), 支撑全部场景查询
ingest_tasks       导入任务(含处理速率: 单篇平均耗时)
```

## API 一览

| 方法 | 路径 | 说明（任务） |
| --- | --- | --- |
| POST | `/api/v1/datasets/upload?engine=rule` | 上传 zip 数据集，后台自动解析入库（任务三） |
| GET | `/api/v1/datasets/tasks/{id}` `/tasks` | 导入任务状态/速率 |
| GET | `/api/v1/announcements` `/announcements/{id}` | 公告列表（关键词/采购单位/类型/日期/金额区间）+ 详情 |
| GET | `/api/v1/items` `/items/{id}` | **标的物全字段检索**：product_name/category/brand/spec/价格区间/数量下限/来源 |
| GET | `/api/v1/orgs` `/orgs/{id}` `/orgs/{id}/profile` | 主体列表 / 画像（中标·投标·合作统计 + 项目清单） |
| GET | `/api/v1/scenarios/1?procurement_unit=` | 场景1：采购单位 → 长期/大量合作中标供应商与产品供应商（合作次数、金额） |
| GET | `/api/v1/scenarios/2?procurement_unit=` | 场景2：采购单位 → TOP5 高频投标主体 + 高频协同投标组合 |
| GET | `/api/v1/scenarios/3?supplier=` | 场景3：中标供应商 → TOP5 共同竞标主体 + 全部参与主体（频次、总金额） |
| GET | `/api/v1/scenarios/4?suppliers=A,B` | 场景4：多个中标供应商 → 均合作的采购单位（频次、金额） |
| GET | `/api/v1/scenarios/5?suppliers=A,B` | 场景5：多个中标供应商 → 共同竞标项目与结果（项目数、总金额） |
| GET | `/api/v1/stats/overview` `/stats/graph` | 统计概览（覆盖率/字段填充率）与图谱数据（节点+边） |
| GET | `/api/v1/health` `/` `/docs` | 健康检查 / 元信息 / Swagger 文档 |

所有查询响应 < 数毫秒～数十毫秒量级（本地索引），满足赛题「单次查询响应 < 1 秒」性能要求。

## 命令行

```bash
python -m app.cli ingest <数据集目录或zip> [--engine rule|llm|hybrid] [--limit N]  # 批量导入

python -m app.cli reset     # 清空数据库

```

## 运行与部署说明

- 数据与数据库默认落在 `backend/data/`（`dsh.db`，SQLite WAL 模式），可用 `DSH_DATA_DIR` 修改。
- 服务绑定 `DSH_HOST/DSH_PORT`（默认 `0.0.0.0:8000`）；若端口被占用可 `python run.py --port 8010`。
- **内置可视化平台**：`http://localhost:8010/platform`（数据看板 / 标的物检索 / 公告浏览 / 5 大场景分析 / 关系图谱 / 数据导入，ECharts 已本地化、可离线演示；`/static` 供静态资源）。若另行开发 Vue 前端，指向本服务 API 即可，`/docs` 提供交互式调试入口。
- 附件 `.doc` 解析依赖 LibreOffice（`LIBREOFFICE_PATH`）；图片 OCR 依赖 paddleocr（可选安装）。
- LLM 引擎（`EXTRACTION_ENGINE=llm/hybrid`）支持长文本自动分块抽取（HTML 最多 4 块 × 9000 字 + 附件 2 块）+ 结果合并去重 + 失败自动重试 1 次。

## 基准测试数据集全量验证（赛题五基准测试数据, 1038 篇公告 + 970 个附件包, rule 引擎）

对赛事提供的基准测试数据集（`赛题五.基准测试数据_html` 与 `赛题五.基准测试数据_file`，附件经 zip 解压后约 5.6 GB、含 1785 个 PDF / 619 个嵌套 zip / 107 docx / 50 doc / 32 rar 等）完成全量解析与入库，结果如下：

| 指标 | 值 |
| --- | --- |
| 公告总数 / 解析成功率 | 1038 / **100%**（0 失败; 去重后 1032 篇） |
| 标的物条目 | 6371 条（已过滤序号/包号等噪声名; 7 字段提取率见下） |
| 市场主体（组织） | 8698 个（采购单位 766 / 中标供应商 2164 / 投标参与方 3679 / 产品供应商 1570 / 代理机构 519） |
| 参与关系 | 10527 条（角色 + 包号 + 金额） |
| 中标（成交）信息覆盖 | 1035/1038 篇（3 篇公文中标栏位在 PDF 附件中为空白表单/图片，2.9‰） |
| 单篇 HTML 平均解析耗时 | ~10 ms |
| 含附件单篇平均处理 | ~1.1 s（5.6 GB 附件全量约 19 分钟） |
| 标的物检索响应 | ~7 ms（q=服务, 20 条） |

7 字段提取率（对 6371 条标的物）：产品服务名称 **100%**、品目 **57.7%**（名称关键词分类推断，公告本身带"品目"列的仅 ~6%）、品牌 65.1%、规格型号 66.7%、数量 60.9%、单价 51.1%、总价 50.1%。单价/数量对大量"服务类"标的天然缺失——此类标的只有服务范围无单价数量，实为数据自身特性。

数据多样性覆盖情况（全部已支持并在全量测试通过）：

| 布局/形态 | 样例 |
| --- | --- |
| 标准列式标的表（货物名称/品牌/规格型号/数量/单价/总价） | 中央广播电视总台 5G+8K 项目等 |
| 中标信息表（包号/供应商/地址/中标金额，含合并单元格） | 河南/广西/山西 结果公告 |
| 山东"成交信息"段落式（`三、 成交 信息` / `成交 供应商名称：`） | 山东网格式公告 |
| 单元格内嵌键值对（`名称：X 品牌：Y 数量：N 单价：P` 单行多键 / 纵向单键多行） | 云南/潍坊 明细表 |
| 单格整段文本键值（`项目名称：… 服务范围：…`） | 潍坊运维服务公告 |
| 行内键值对中标表（`标 包 / A / 供应商名称 / X公司 / 供应商地址 / …`） | 微山县成交公告 |
| 供应商名单表（无金额）→ 中标供应商 / 资格审查表 → 投标参与方 | 河北/山东 公告 |
| 嵌套压缩包（zip 内含 zip/docx/pdf）递归解析（深度≤3） | 山东 附件包 |
| 联合体中标（`XX(联合体成员：A、B)` → 只留牵头单位） | 广东/哈尔滨 公告 |
| 金额格式 | 元/万元/大写中文金额/千分位/`￥`/`（元）`标注、`单价(元)：` 等 |
| 编码 | UTF-8 全量通过；附件文本按 GBK/UTF-8 容错处理；评分拼接/套话/超长串等噪声已过滤 |
| 名称清洗 | 序号/包号误当名称（`1`、`1-3`、`01包`）在解析末端过滤；`1标段 XX` 等包前缀从名称中剥离 |

已知局限（文档化说明）：3 篇公告（`t20260601_26667045`、`t20260707_26890255`、`t20260812_27123683`）的 html 与附件中均无可用文本形式的中标信息（PDF 表单字段为空/图片），经规则引擎无法提取中标供应商，属数据本身缺失或需 OCR 的边界样本；`.rar/.7z/.wps/ppt 图片` 附件未内置解压/渲染，仅登记不抽取文本（可挂接 7z/OCR 增强）。
